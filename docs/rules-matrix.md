# Rules matrix

Audited on 2026-11-10 for the supported ruleset. This document is the
implementation baseline for issue #19: it records what the engine automates,
what stays a Storyteller decision, what is untested, and what is unsupported.
It is not a rules authority by itself: a `verified` row cites a permanent wiki
revision and at least one named test; the other rows record their status. The
durable behavior contract derived from the `verified` rows lives in
`openspec/specs/`; this matrix stays the audit table for `host-choice`,
`implemented-unverified` and `unsupported` cases.

## Status legend

| Status                   | Meaning                                                                                                                                             |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `verified`               | The official text is pinned, the engine implements every behavior named in the row, and at least one listed test asserts it.                        |
| `implemented-unverified` | The engine has code or a step for the mechanic, but no test asserts it, or the test covers only part of it.                                         |
| `host-choice`            | The official text leaves the decision to the Storyteller. The app creates a step and stores the input, but does not resolve the rule automatically. |
| `unsupported`            | The mechanic is not modeled. The host must resolve it outside the engine, and the app must not present it as automated.                             |

A row marked `host-choice` or `unsupported` is not a defect by itself: the
issue requires the app to expose only legal options and to mark manual
resolution. It becomes a defect when the app claims automation it does not
have, or when it offers no legal host control.

## Baseline

Run `npm test` on Node 24. The suite lives next to the code it covers:
`src/core/engine`, `src/core/model`, `src/core/commands`, `src/application`,
`src/infrastructure`, `src/entry` and `src/ui`. This document does not repeat
per-file test counts; `npm test` and the cited tests are the source.

The browser regression script `scripts/browser-check.mjs` is not part of
`node --test`; it runs in pull-request CI with Playwright.

### Reproducible defects found by the audit

These are recorded as RED candidates for later TDD PRs. An item is marked
fixed only when its RED test and the minimal implementation are in the same
change.

1. **Fixed: Pukka was partial.** The engine now stores the poison as an effect
   and the delayed death as a `pukka-death` effect. The next Pukka step (or an
   Exorcist skip) resolves the previous victim, clears the poison and applies
   the new poison. Self-target suspends the previous death, makes that victim
   healthy and self-poisons the Pukka; a healthy Pukka resumes the suspension
   immediately, and dies as the previous target when it chooses again. Poison
   and drunk effects resolve in one dependency graph: a living impaired source

2. **Fixed: Juggler information was always 0.** `svInfoForStep` returned
   `{ kind: "number", value: 0 }` with no `needsChoice`, so `givenSelect`
   rendered no override. The first-day guesses are now recorded by the
   `jugglerGuess` command and the night answer counts the matches; a host
   override exists when the Juggler is impaired or a Vortox is in play.
   Tests: `src/core/engine/snv.test.ts`; `src/core/engine/snv.test.ts`.
3. **Fixed: Fang Gu could jump more than once.** `recordSvOutcome` stored the
   `used.fanggu` flag on the old Demon, and the new Fang Gu started without it,
   so a second Outsider kill jumped again. The wiki says the ONCE reminder stays
   in the centre for the rest of the game (r2974). A game-scoped

4. **Fixed: Repeat-target restrictions were not enforced or were over-scoped.**
   Devil's Advocate and Exorcist say "different to last night". The engine
   stores each actor's last target with its night, rejects a repeat with
   `error.50` only while the choice was on the immediately preceding night, and
   lets a skipped night, a death or a role gap clear the restriction. Legacy
   target records without a night are treated as unknown. RED to GREEN tests:

5. **No event log or replay (resolved by #30).** The audit found a 12-snapshot
   undo ring instead of a deterministic event log. `state.journal` and
   `replay` now replace the ring; see the "Event log and deterministic replay"
   row and `openspec/changes/archive/2026-11-12-event-log-replay/`.
6. **Two roles have no engine handling.** Artist and Savant are `unsupported`
   below. Pacifist, Tinker and the other `host-choice` rows keep a legal host
   control. This is explicit, not silent fallback.
7. **Travellers, Fabled and Loric are not modeled; jinxes are now pinned.** An
   imported script may list Travellers; they are collected and ignored for the
   deal, and the script still needs five standard roles and all required teams.
   Fabled and Loric stay outside the supported set. The seven official jinx
   pairs whose two characters are supported are pinned in
   `docs/official/jinxes.json` and `src/core/model/jinxes.ts`; every pair has
   its official reason, a snapshot source and a test:
   `src/core/model/support.test.ts` "the jinx table is versioned and every applicable pair has a source and a reason". The app lists the pair but does
   not resolve it, so a pool that can trigger a jinx is reported as
   `requires-storyteller-choice`.
8. **Fixed: several automated mechanics had no test.** Courtier, Innkeeper,
   Gambler and Shabaloth effects, the Sailor's drunk recipient, the Moonchild's
   next-night kill, and the Godfather's information and kill now have asserting
   tests (`src/core/engine/bmr.test.ts`), and their rows are `verified`.

### Unknown and unverified rules

- Every active Cerenovus and Mutant madness condition has a separate review
  keyed to its effect; `endDay` is blocked until all are decided. Whether a
  player was mad stays a Storyteller judgement.
- Pit-Hag, Barber, Snake Charmer and Philosopher character changes are limited to the tested paths; arbitrary corrections are not applied.
- Vortox false information and impaired information are host-supplied: the engine requires a host answer instead of presenting the computed truth, but the lie itself is the Storyteller's.
- Pacifist survival and Tinker death have no state model; the host records them with the execution and outcome controls.
- The Chambermaid count, the Assassin's once-per-game rejection and the Evil Twin both-live block have no dedicated test, so their rows are `implemented-unverified`.
- Registration after death is asserted for the Recluse and Spy lookup; other registration-dependent queries remain review tasks.
- Jinx pairs among the supported characters are pinned in the versioned table;
  the app lists the pair and the Storyteller resolves it, so no jinx is claimed
  as automated.

## Update procedure

1. Fetch the scenario pages and every role page revision with
   `https://wiki.bloodontheclocktower.com/api.php?action=query&prop=revisions&rvprop=ids|timestamp&format=json&titles=...`.
2. Compare the revision ids with the per-row links. A changed revision needs a
   rules review, not an automatic update.
3. Update the row, its source link and its test in the same change.
4. Never mix a new revision with the pinned `docs/official` snapshot in one
   game. The snapshot is the engine data; the wiki revision is the rule claim.
5. Run `npm test` and the affected route before reporting.
